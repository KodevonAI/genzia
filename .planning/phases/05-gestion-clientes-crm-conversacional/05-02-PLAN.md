<objective>
Fix the second research-flagged blocker: `classifyAndExecute` currently
unconditionally requires a well-formed UUID `clientId` on every tool call
(lines ~94-100 today), which rejects `create_client` (no client exists yet)
and `list_clients` (agency-wide search, no single client) outright,
regardless of how correctly those tools are implemented. This plan makes
that requirement conditional per tool name, while leaving the scope
cross-check fully intact for the two tools that ARE client-scoped
(`update_client`, `get_client`) — the exact injection vector RESEARCH.md's
Security Domain section already analyzed (a dictated `clientId` steering a
tool call toward a different client).

Purpose: this plan and 05-01 are the two hard prerequisites RESEARCH.md
flags as gating everything else — no create/update/list/get agent tool can
be exercised correctly until this lands.
Output: `classifyAndExecute` accepts agency-scoped tool calls with no
`clientId`, and the 4 new tool names are registered in the risk map.
</objective>
