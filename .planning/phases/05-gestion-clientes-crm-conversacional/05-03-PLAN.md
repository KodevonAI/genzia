<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Web form input → createClientAction/updateClientAction | Untrusted form data; agencyId/identity are never accepted as parameters, only derived from the real Clerk session |
| Agent tool input → createClient/updateClient | `identity`/`agencyId` are supplied by server-side caller code (`runTurn`/`classifyAndExecute`), never by the model's own tool-call arguments |
| Merge-based partial update → DB invariants | A patch that omits a field must not silently bypass D-02's phone-or-email invariant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08 | Elevation of Privilege | createClientAction/updateClientAction accepting a caller-supplied agencyId/identity | mitigate | Neither function's signature takes those parameters at all; both derive them from `auth()` + `withTenantContext` inside the function body, matching `updateBrandConfig`'s established pattern. |
