<objective>
Extend the `clients` table with the real CRM fields (D-01/D-02/D-03/D-04), and fix
the one RLS gap RESEARCH.md flags as a hard blocker for everything else this
phase does: `clients_write_admin_only` (migration 0001) currently rejects every
non-admin INSERT/UPDATE on `clients`, which makes D-13 ("cualquier miembro

`agent_action_catalog` with the 4 new tool codes this phase needs (D-08/D-17).

to `clients` as a non-admin team member. Nothing downstream can be exercised
correctly until this schema + RLS + catalog foundation exists.
Output: 3 new migrations (0020/0021/0022), the extended `clients.ts` schema,
and `lib/clients/industries.ts`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Team member role → clients write access | `app.role`/`app.team_member_id` GUCs, set by `withTenantContext`/`withResolvedIdentityContext` from the caller's real session/identity, never from request input |
| agent_action_catalog risk level | Platform-global, no RLS, SELECT-only grant to `app_user` — read by `classifyAndExecute`, never influenced by tool input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | `clients_insert_by_team_member` / `clients_update_by_role` | mitigate | Both policies check `agency_id` against `current_setting('app.agency_id', true)` and role/assignment against the caller's real GUCs, set exclusively by the two tenant-context helpers — never a client-supplied value. |
| T-05-02 | Tampering | A member editing a client outside their assignment | mitigate | `clients_update_by_role`'s `WITH CHECK` re-validates the same predicate on write, not just `USING` on read; an unassigned member's UPDATE affects 0 rows. |
| T-05-03 | Tampering | Reused pooled connection returning `''` instead of `NULL` for `app.team_member_id` | mitigate | `NULLIF(current_setting('app.team_member_id', true), '')::uuid` per the 0002/0007 lesson — a bare `::uuid` cast on `''` would throw instead of failing closed. |
| T-05-04 | Elevation of Privilege | A forged catalog code driving risk classification | accept (unchanged from Phase 4) | `agent_action_catalog` has no RLS but also no application-level write path outside migrations; `classifyAndExecute` only ever reads it by a hard-coded tool-name map, never by anything in `toolUse.input` — this plan only adds seed rows, the enforcement itself is plan 05-02's. |
</threat_model>
