## Trust Boundaries

| Boundary | Description |

| Clerk session → agency scope | `orgId` from `auth()` is the only trusted source of `agency_id` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Elevation of Privilege | Non-admin invoking `addAuthorizedContact` / `removeAuthorizedContact` directly (SEG-03) | mitigate | `assertCallerIsAdmin(tx, userId)` inside the transaction plus `authorized_contacts_write_admin_only` RLS — two independent layers, matching `assign-client.ts`'s documented reasoning. |
| T-02-12 | Spoofing | Caller supplying `agencyId`, `optInConfirmedBy`, or `optInConfirmedAt` to forge an attestation or cross-tenant write | mitigate | All three derived server-side: `agencyId` from `orgId`, `optInConfirmedBy` from `assertCallerIsAdmin`'s returned row, `optInConfirmedAt` from `new Date()`. Acceptance criteria assert the input-sourced variants are absent. |
| T-02-07 | Repudiation | Contact added without a recorded consent attestation (SEG-04) | mitigate | Strict `input.optInConfirmed !== true` rejection before any write, plus the DB CHECK from plan 02-02 as the backstop. |
| T-02-02 | Elevation of Privilege | Phone number reused across clients or colliding with a team WhatsApp number | mitigate | Enforcement is the unique index + migration 0006 trigger; this action only translates the failure into `phone_already_linked` with the owning client's name (D-08). | T-02-05 | Information Disclosure | Contact PII exposed to a scope that should not see it | mitigate | `listAuthorizedContacts` adds no filter of its own and relies on `authorized_contacts_select_team_only`, which excludes `client_contact` (SEG-08, D-09). |
