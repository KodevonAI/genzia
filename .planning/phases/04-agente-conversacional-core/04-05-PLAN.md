Create `lib/whatsapp/media.ts`:

```typescript
export const MEDIA_LIMITS = {
  audio: { maxBytes: 16 * 1024 * 1024, mimeTypes: ["audio/mpeg","audio/aac","audio/amr","audio/mp4","audio/ogg"] },
  image: { maxBytes: 5 * 1024 * 1024,  mimeTypes: ["image/jpeg","image/png"] },
} as const;

export type DownloadedMedia = { buffer: Buffer; mimeType: string; byteLength: number };

export async function downloadMedia(mediaId: string): Promise<DownloadedMedia>;
```

Implementation:
1. `requiredEnv("META_WHATSAPP_ACCESS_TOKEN")` and
   `requiredEnv("META_WHATSAPP_PHONE_NUMBER_ID")` — local helper copied from
   `send-message.ts`, same error text.
2. Step 1: `GET https://graph.facebook.com/${GRAPH_API_VERSION}/${mediaId}?phone_number_id=${phoneNumberId}`
   with `Authorization: Bearer ${accessToken}`. Non-OK → throw
   `` `Meta media lookup failed (${res.status}): ${await res.text()}` `` — status
   plus Meta's own error body, never the request headers.
3. Parse `{ url, mime_type, file_size }`. If `file_size` is present and exceeds
   the limit for that mime type's family, throw
   `` `Media ${mediaId} is ${file_size} bytes, over the ${family} limit of ${max}` ``
   WITHOUT performing step 2 — do not download bytes you are going to reject.
4. Step 2: `GET url` with the SAME `Authorization: Bearer` header. Comment
   explaining that this header is required on the second request too, and that
   this is precisely why the URL cannot be handed to the model as a
   `source: {type: "url"}` content block (the model's fetcher cannot attach
   Genzia's token, so it would 401).
5. `Buffer.from(await res.arrayBuffer())`; re-check the actual byte length
   against the limit (Meta's `file_size` is advisory) and throw the same
   message if over.
6. Return `{ buffer, mimeType: mime_type, byteLength }`.

Header comment: Phase 3 stored `media_id` only (D-05) and this is the function
that closes that gap for WA-05; the 5-minute URL expiry means the two steps
must happen in the same execution, never across an Inngest step boundary.

No `import "server-only"` (the verification script imports this under `tsx`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Meta media CDN → Genzia server | Attacker-influenced bytes of attacker-chosen size and type arrive here |
| Media bytes → LLM context | A voice transcript is untrusted text that will sit in the same window as the tool definitions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-21 | Denial of Service | Oversized media download | mitigate | `file_size` from Meta's step-1 metadata is checked BEFORE step 2 runs, and the real byte length is re-checked after; both use Meta's documented 16 MB / 5 MB limits. Asserted offline (assertion 5). |
| T-04-22 | Information Disclosure | Access token in an error message or log | mitigate | Thrown errors carry HTTP status + Meta's error body only, mirroring `send-message.ts`; asserted offline (assertion 6) by checking the token value is absent from the message. |
| T-04-23 | Spoofing | Handing Meta's temporary URL to the model as a fetchable source | mitigate | Prohibited by construction — the bytes are downloaded server-side and passed as base64. The rationale is a code comment so a future contributor does not "simplify" it back. |
| T-04-24 | Tampering (prompt injection) | Voice transcript / image text steering a tool call | mitigate | Transfers to plan 04-06: the transcript is ordinary user content and every tool call it can produce still passes the risk interceptor's deterministic checks (SEG-10). No mitigation is attempted at the transcription layer, where it would be theatre. |
| T-04-25 | Denial of Service | Deepgram outage losing the whole turn | mitigate | `transcribeAudio` never throws; a failed transcription degrades to a labelled placeholder so the agent can still respond and say it could not hear the note. |
</threat_model>
