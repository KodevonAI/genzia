<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server process → OpenRouter/Anthropic/Deepgram | API keys leave the process in an Authorization header; they must never re-enter logs or client-visible errors |
| System prompt construction → LLM context | The only place where an identity's data scope is stated in natural language; it must never over-grant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Information Disclosure | API keys in error paths | mitigate | `lib/agent/client.ts` follows `send-message.ts`'s convention: thrown errors carry HTTP status + provider error body only, never the request headers. No key value is ever passed to `console.*`. |
| T-04-08 | Spoofing (SEG-09) | System prompt | mitigate | `AI_DISCLOSURE_RULE` spliced unconditionally before any branching; `scripts/verify-agent-prompt.ts` asserts all four identity branches contain it verbatim and runs in the offline gate. |
| T-04-09 | Information Disclosure | Cost/caching regression via wrong endpoint | mitigate | Exactly two `new Anthropic(...)` call sites exist, both in `lib/agent/client.ts`, both native-wire-format; grep-asserted. `.env.example` documents the `/api/v1` trap. |
| T-04-10 | Denial of Service | OpenRouter outage with no SLA | mitigate | Consecutive-failure counter switches to the direct Anthropic endpoint; when no `ANTHROPIC_API_KEY` exists the degradation is logged loudly rather than silently no-op'd. |
</threat_model>
