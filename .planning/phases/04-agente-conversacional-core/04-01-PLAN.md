Close the two real RLS gaps Phase 4's research found by direct migration
inspection, before any code in this phase reads `audit_log` or `messages`
broadly.

Gap 1 — `audit_log` (migration 0006) has ZERO role branching: a plain
`agency_id = current_setting('app.agency_id', true)` for both USING and WITH
CHECK. Any resolved identity that reaches an `app.agency_id` scope — including
a `client_contact` — can read the entire agency's internal action log. 0006's
own comment says the shape was deferred to "Phase 4's concern". This is that
plan.

`member` into one branch with NO `client_assignments` check, so any member can
read every client's WhatsApp history. This directly contradicts STATE.md's
documented hard invariant ("Convención de tres ramas para RLS en toda tabla
client-scoped futura... Copiar solo dos ramas reintroduce en silencio la fuga
que esta fase existe para prevenir").

Purpose: both fixes are pure SQL with no application-code dependency, so they
ship first — every later plan in this phase reads through these policies.
Output: two migrations, one real-Neon verification script.
</objective>
